# TMC 聊天记忆（轻量版）for AstrBot

给「只聊天」的机器人用的长期记忆插件。没有工具调用、没有多分区、不挑模型——插件自己记录、自己压缩、自己注入。

## 和完整版的区别

| | 完整版 `astrbot_plugin_tmc` | 本插件 |
|---|---|---|
| 记忆区 | L/D/E/F/G 五区 | 只有 L（聊天） |
| 工具 | 5 个 `memory_*` | **无**，不依赖 function calling |
| 回忆方式 | 模型主动调工具 | 每轮按你的话**自动检索**并注入 |
| 注入 | L5 + D1 标题 + L1 + E3/F3 | 理解 + 记忆索引 + 稍早摘要 |
| 每轮开销 | 约 1000~1200 token | 约 300~500 token |
| 适合 | 角色扮演 + 群聊 + 游戏 + 阅读 | 一对一日常聊天 |

她的行为不需要任何改变：模型只要正常聊天，记忆就在背后工作。

## 怎么工作

```
L1 最近对话（1200 字）→ 满了压成摘要进 L2
L2 摘要（2000 字）→ 满了归档：索引进 l3、文本进 l4、抽取事实卡、重算「理解」
每轮注入：事实卡 + 理解 + 按这句话检索到的旧事 + 最近 6 条索引 + L2 末尾 600 字
新会话开头：额外带一次 L1 结尾，把上一段接上
```

事实卡（`facts.json`）是把「约定 / 偏好 / 称呼 / 雷点」单独抽出来，每轮固定注入，
不依赖检索，所以「你答应过周末去看海」这种话不会因为索引稀释而丢。

所以：

- **不需要工具也能回忆细节**：每轮拿你说的这句话去 L3/L4 本地检索（纯字符串匹配，不调模型），命中就把摘要 + 原文片段一起注入。
- **越久的事压成索引**，每轮都看得到。
- **换会话不丢**：新会话第一轮自动交接上段结尾。
- **聊得再久，注入量固定**，不会随对话变长而变贵。

## 安装

1. 把 `astrbot_plugin_tmc_chat/` 放进 `data/plugins/`。
2. WebUI → 插件 → 启用「TMC 聊天记忆（轻量）」。
3. 数据在 `data/plugin_data/astrbot_plugin_tmc_chat/chat/`。

无第三方依赖。

## 到底存了什么

| 文件 | 内容 | 会不会留全部聊天 |
|---|---|---|
| `l1.md` | 最近对话原文，一行一条 | **不会**，超过 1200 字就压进 L2 并清空 |
| `l2.md` | 压缩后的摘要 | **不会**，超过 2000 字就归档并清空 |
| `l3.jsonl` | 每条归档的索引（60~120 字） | 只有索引，永久 |
| `l4.jsonl` | 归档时的**摘要文本**（不是逐字记录） | 只有摘要，永久 |
| `l5.json` | 对你的理解，80~150 字 | 单条，覆盖式更新 |
| `facts.json` | 事实卡：约定/偏好/称呼/雷点，每条 ≤80 字 | 最多 24 条，合并去重 |
| `vectors.json` | 归档页的向量（本地模型算的） | 每页 1024 维，可随时重算 |
| `raw/日期.md` | 压缩前的逐字原文（`archive_raw` 开启时） | 永久，按天分文件 |

默认 `archive_raw: true`：每次压缩前先把 L1 原文追加进 `raw/YYYY-MM-DD.md`，所以完整对话**不会丢**。这些文件不参与注入、不花 token，只占磁盘；不想要就关掉。

不开启时，逐字全文不会长期保留：L1 只留最近 1200 字，之后只剩越来越短的摘要。

另外，AstrBot 自己的会话历史存在 `data/data_v4.db`，那才是"全部聊天记录"，和这个插件无关，清不清由 AstrBot 的会话设置决定。

## 导入安装之前的聊天

插件只能看见装好之后的对话。旧记录在 AstrBot 自己的 `data/data_v4.db` 里，用附带的 `import_history.py` 导进来（只读打开数据库，不改原库，不调模型）：

```powershell
# 在插件目录里执行，路径会自动推算，不用改
cd '<你的 AstrBot 根目录>\data\plugins\astrbot_plugin_tmc_chat'

& python import_history.py --list          # 看有哪些会话
& python import_history.py --all --dry-run # 试运行
& python import_history.py --all           # 正式导入
```

也可以只导一个会话：`--conversation <id>`。

导入结果：

- 原对话写进 `raw/import-日期.md`
- 按约 1200 字切块，写进 L3/L4（带摘要），自动回忆能检索到
- 最后 1200 字接进 L1，当前对话可以直接延续

脚本会自动从插件所在位置推出：

```
<AstrBot>/data/data_v4.db                          ← 会话库
<AstrBot>/data/plugin_data/astrbot_plugin_tmc_chat/chat  ← 记忆目录
```

路径不同时用 `--db` 和 `--data-dir` 指定。

### 从 QQ 导出的聊天文本导入

如果手里有导出的聊天记录（txt/md/json，比如 QQ 的“导出消息记录”），直接丢给脚本：

```powershell
& python import_history.py --file "D:\聊天备份\export.txt"
```

- 自动识别 UTF-8 / GBK / UTF-16
- 按约 1200 字切块，和数据库导入走同一套流程
- 可以重复写多个 `--file`

格式不挑，只要能读出文字；如果是 `.mht` / `.html`，先用浏览器或工具转成 txt。

## 语义检索（可选）

如果配了 embedding 提供商（比如 Ollama 的 `bge-m3`），归档页会在后台自动转成向量，
检索变成「向量 65% + 关键词 35%」的混合排序：

- 问「海边那次」也能命中「看海」那页
- 不消耗 API token（向量在本地算）
- 首次会给已有的页补向量，每 60 秒补 24 页

关掉就退回纯关键词检索。

### 从「记忆本」导入事实

如果手里有一份 Markdown 记忆本（`## 用户` 下面一条条列着用户信息），可以直接灌进事实卡：

```powershell
& python seed_facts.py --file "D:\记忆本.md" --dry-run
& python seed_facts.py --file "D:\记忆本.md"
```

- 默认只取「用户」这一节（「我是谁」是机器人自己，不该进事实卡）
- 按关键词自动分类型：称呼 / 约定 / 偏好 / 雷点 / 事件
- 可加 `--section 用户,环境` 选多节
- 已存在的事实不会重复添加

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `auto_capture` | `true` | 自动记录对话 |
| `inject` | `true` | 每轮注入 |
| `inject_max_chars` | `1200` | 注入上限，约 800 token |
| `keep_index` | `6` | 注入几条历史索引 |
| `auto_recall` | `true` | 按消息自动回忆旧事 |
| `vector_recall` | `true` | 用向量做语义检索（需 embedding 提供商） |
| `embedding_provider_id` | 空 | 指定向量模型，留空自动选第一个 |
| `facts_max_chars` | `400` | 事实卡注入上限；填 0 关闭 |
| `facts_limit` | `24` | 最多保留几条事实 |
| `l1_max` | `1200` | L1 压缩阈值 |
| `line_max_chars` | `300` | 单条消息最多记多少字（她的长回复会被截断） |
| `archive_raw` | `true` | 压缩前把逐字原文存到 `raw/日期.md` |
| `l2_max` | `2000` | L2 归档阈值 |
| `tick_interval` | `60` | 后台检查间隔（秒） |
| `base_dir` | 空 | 自定义数据目录 |

## 指令

- `/tmc` — 看状态（L1/L2 占用、归档页数、事实条数）
- `/tmc 索引` — 看有多少页索引待重建
- `/tmc 索引 重建 50` — 把导入留下的长索引重建成正式摘要（一次性）
- `/tmc 事实` — 看事实卡
- `/tmc 事实 重算` — 从最近 5 页归档重新抽取
- `/tmc l5` — 看「她对你的理解」
- `/tmc l5 重算` — 重新生成理解
- `/tmc seal` — 立刻压缩一次
- `/tmc log` — 最近的压缩记录

指令不消耗 token。

## 成本

按每轮 60 字估算：

- 注入约 300~500 token/轮
- 后台压缩：约 120 轮触发一次「L1→L2」，约 240 轮一次归档 + 重算理解，摊到每轮约 30 token

100 轮/天 ≈ 4~5 万 token，大约是完整版的 1/3。

## 已知限制

- **回忆靠关键词，不是语义**：检索是中文 2-gram 匹配 + 标签，换个说法（“海边” vs “看海”）可能漏；没有向量检索。要更聪明用完整版的 `memory_recall`。
- **模型不可用时会退化**：压缩要调模型，调不通时 L1 只保留最近一半（日志里记 `l1-trim`），不会无限增长，但也不再形成摘要。
- **群里也记进同一个 L1**：如果只做一对一聊天，这没问题；群聊和私聊混用会串。
- **多个人格共用一份记忆**：同一实例里所有会话共享（换 `base_dir` 可隔离）。
- **没有阅读/游戏/日记**：那是完整版的能力。
